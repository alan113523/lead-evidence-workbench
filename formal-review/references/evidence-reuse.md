# 证据复用与缺口补查

适用于同一轮多商机复用企业背景，以及后续运行复核已有来源。复用是减少重复阅读与整理，不扩大授权范围、不降低研究门禁。

## 建立一次本轮证据索引

以经确认的企业主体键关联公司名和独立身份锚点，不按同名、账号昵称或业务员归并。买家账号、会话、公司主体是不同层级；跨店聊天分别保留来源。同一主体多条商机可以共享企业背景，本次采购需求仍按消息时间和商机关联分别判断。

索引至少记录：主体键和匹配依据、支持的事实/核验类别、公共 URL、发布主体与独立性组、访问/观察时间、证据文件及哈希、本轮适用性判断、限制。客户整段私有聊天只在本机作为非公开证据，不作为检索词或网页来源；其中明确给出的最小必要公司/联系线索可依项目公开背调规则用于已授权商业研究，不能把聊天本身升级为公开来源。仅整理统一研究输入时不启动真实检索。

依次作三种决定：

| 决定 | 条件 | 动作 |
| --- | --- | --- |
| 复用 | 同一主体、原证据可读取、支持本轮所需事实且仍适用 | 引用原来源和实际观察时间，记录本轮复核理由，不重复复制全文 |
| 刷新 | 企业身份有变化、资料过时、风险/付款等当前状态、结论冲突 | 定向重新访问或检索，保留新旧观察，解释变化 |
| 补查 | 原来未查、来源打不开、未可靠匹配、仅有无来源结论 | 列入缺口队列，实际尝试后记录成功或限制 |

不能统一假定所有证据有效30天或永久有效。历史事实可复用其当时范围；当前存续、法律/合规/声誉状态按本轮需要重新核验。历史“没有搜到”不证明当前无风险。主体关联变化使旧证据失效，不能直接转移。

## 保留正式门禁

正式 v3 运行仍逐客户完成 identity/legal/compliance/payment/reputation 五类实际尝试，九维缺证据保留不足。每个 `attempts` 必须有本轮真实执行/复核的观察；不能把旧 checkedAt 改成今天、批量填 passed，或只复制旧报告当成本轮检索。可共享同轮、同主体、同问题的实际公开观察，并在各记录引用同一来源；不能跨主体复用结论。

旧证据是搜索线索和背景资料。本轮规定必须刷新时，访问/搜索动作仍需执行。实际工具不可用按原契约 block；已尝试但证据不足才记录 limited。原研究/报告契约、名单扫描、完整引用与 PDF 逐页视觉检查继续生效。

## 缺口队列与覆盖回执

先在本地列出 `主体 → 核验类别 → 已有证据 → 复用/刷新/补查 → 理由`，只执行后两类的缺口工作；正式流程需要的本轮尝试仍逐项完成。不要反复整批重读聊天。读取报价、数量、付款等关键语句时保留相邻上下文和发送方，买家付款陈述不等于已核到账。

交付分别列：原始商机数、去重会话数、窗口前往来排除数、聊天范围完成/待续/异常数、公开研究尝试人数、可靠主体匹配人数、画像复核人数、正式 v3 校验状态。运营画像完成不能替代完整企业研究；资料不足不补零、不强行定性。

新旧客筛选只剔除后续深采/研究队列，不删除原台账、来源或原有结论。对已锁定的 v3 输入，范围变化必须建立新运行，不能在原运行删客户规避校验。
